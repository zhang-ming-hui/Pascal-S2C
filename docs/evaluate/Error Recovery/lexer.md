# 词法分析中的错误恢复策略详解

| 策略名称 | 核心工作原理 | 适用场景与优点 |
| :--- | :--- | :--- |
| **1. 删除/跳过非法字符**<br>*(Panic Mode 词法版)* | 遇到无法匹配任何正则规则的字符时，直接**丢弃**该字符，跳过并继续扫描下一个字符，直至成功匹配合法 Token。 | **场景**：代码混入乱码或不支持的特殊符号（如 C 语言中出现 `@`）。<br>**优点**：实现最简单，能保证扫描流程不中断。 |
| **2. 生成错误标记**<br>*(Error Token 传递)* | 将无法识别的字符序列**打包**成一个特殊 Token（如 `TOKEN_ERROR`），附带错误信息后照常传递给语法分析器。 | **场景**：IDE、代码格式化工具、现代编译器（如 Clang）。<br>**优点**：不丢失源码字符，保持词法分析器纯粹性，将错误处理决策推迟给语法阶段。 |
| **3. 强制闭合/插入缺失字符** | 针对有明确边界界定符的 Token，当检测到换行或 EOF 时，**强制插入**缺失的右界定符（如 `"` 或 `*/`）。 | **场景**：未闭合的字符串或注释。<br>**优点**：将错误影响范围严格限制在当前行或块内，防止吞噬后续大量代码。 |
| **4. 字符替换**<br>*(智能纠正)* | 捕捉人类易犯的特定手误（如全角标点 `，`、`；`），将其**替换**为正确的半角字符，生成正常 Token。 | **场景**：提升编译器用户体验。<br>**优点**：针对高频手误进行局部修正，给出警告而非报错。 |
| **5. 多次匹配重试**<br>*(最长匹配回退)* | 匹配复杂 Token 失败时，**回退**到上一个合法的状态，将前半部分识别为独立 Token，再重新解析后续字符。 | **场景**：处理科学计数法字面量异常（如 `1.2e+A`）或连续操作符（如 `>>=` 拆解）。<br>**优点**：避免因部分字符非法导致整个字面量解析失败。 |
